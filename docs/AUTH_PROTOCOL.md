# 접속 키 인증 프로토콜 (FTA1)

`run --auth` 의 인증 관문과 접속 도우미가 주고받는 형식입니다. 구현은 세 곳에 있거나 생길 예정이고,
모두 같은 테스트 벡터(`tests/auth_vectors.json`)를 통과해야 합니다.

| 구현 | 위치 | 벡터 검증 |
|---|---|---|
| 서버 관문 + 파이썬 클라이언트 | `fastunnel/auth.py` | `tests/test_auth.py` |
| 윈도우 접속 도우미 중계기 | `client/relay.cs` | `tests/test_relay.py` (윈도우) |
| 전용 접속 클라이언트 (예정, Rust) | 별도 저장소 | 같은 JSON 을 읽어 검증 |

## 흐름

연결이 열리면 **서버가 먼저** 말합니다. 앱 데이터는 3단계가 성공한 뒤에만 오갑니다.

```
1. 서버 → 클라이언트   "FTA1"(4) + 서버 nonce(32)
2. 클라이언트 → 서버   id 길이(1, 1~32) + id(UTF-8) + 클라이언트 nonce(32) + 클라이언트 MAC(32)
3. 서버 → 클라이언트   성공: 0x00 + 서버 MAC(32)
                        거부: 0x01            (그 뒤 연결을 닫는다)
4. 이후 양방향으로 바이트를 그대로 나른다
```

## MAC

```
재료(side) = "FTA1|" + side + "|" + <포트 10진수 ASCII> + "|" + 서버 nonce + 클라이언트 nonce + id(UTF-8)
클라이언트 MAC = HMAC-SHA256(키, 재료("c"))
서버 MAC       = HMAC-SHA256(키, 재료("s"))
```

- **키:** 32바이트. 키 파일과 등록부에는 표준 base64 로 들어 있습니다.
- **포트:** 서버가 지키는 **원격(실제) 포트** 번호입니다. 한 포트의 핸드셰이크를 다른 포트에 쓸 수 없게 묶는 값입니다.
- **id:** `^[a-z0-9][a-z0-9_-]{0,31}$`.
- **비교:** MAC 은 상수 시간으로 비교합니다.

## 이 프로토콜이 하는 것과 하지 않는 것

- **하는 것:** 연결을 연 쪽이 등록된 키를 가졌는지(입장)와 상대가 진짜 서버인지를 서로 확인합니다.
  재전송·반사 방지는 **핸드셰이크 메시지에만** 적용됩니다.
- **하지 않는 것: 채널 보호.** 세션 키 유도나 채널 바인딩이 없습니다. 핸드셰이크 뒤의 바이트는 평문 그대로입니다.
  TLS 는 Cloudflare 에지에서 끝나므로, 에지는 내용을 **읽을 수도, 바꾸거나 끼워 넣을 수도** 있습니다.
  즉 이 방식을 쓰는 것은 Cloudflare 를 **기밀성과 무결성 모두** 신뢰한다는 뜻입니다.
  종단 간 보호가 필요하면 그 위에 별도 암호화 계층이 있어야 합니다(1차 범위 밖).

## 지켜야 할 것

- **nonce 는 CSPRNG 로 32바이트(256비트)씩 만듭니다.** 서버 nonce 는 연결마다 새로 만들고(재전송 방지),
  클라이언트 nonce 도 매번 새로 만듭니다. 구현별 난수원: `auth.py` = `secrets.token_bytes`,
  `relay.cs` = `RandomNumberGenerator`, Rust = `getrandom`. `random` 같은 일반 난수는 쓰면 안 됩니다.
- **방향 태그**(`c` / `s`)가 MAC 재료에 들어가므로 클라이언트 MAC 을 서버 MAC 으로 되돌려 보내는 반사가 통하지 않습니다.
- 클라이언트는 서버 MAC 을 반드시 확인합니다. 확인하지 않으면 가짜 서버(바뀐 gist 주소)에 그대로 붙습니다.
- 서버는 없는 id 에도 같은 계산을 거친 뒤 거부합니다(응답 시간으로 등록 여부를 가늠하지 못하게).
- 핸드셰이크 제한 시간: 서버 3초(정상은 왕복 1번, 약 0.1초). 클라이언트는 cloudflared 를 두 번 거치고
  첫 연결이 느리므로(실측 3.4초, 서버 타이머가 시작되기 전 구간 포함) 더 길게(15~20초) 둡니다.
- **거부는 즉시** 합니다. 키가 256비트라 지연(tarpit)은 대입 방어에 실익이 없고 자원만 묶습니다.
- **미인증 연결 상한**(관문당 128)에 닿으면 새 연결이 아니라 **가장 오래 기다린 미인증 연결**을 끊습니다.
  새 연결을 거부하면 말 없는 연결로 자리를 채워 정상 사용자를 막을 수 있기 때문입니다.
  다만 출발지 IP 가 없는 quick tunnel 에서는 연결을 대량으로 쏟아붓는 DoS 를 완전히 막을 수 없습니다.

## 등록부 (`clients.json`)

- 쓰기는 원자적입니다(임시 파일 + rename, 임시 파일부터 권한 600). 본 파일과 **같은 내용의 백업**
  `clients.json.bak` 을 함께 씁니다.
- 본 파일이 망가지면 백업으로 읽습니다. 같은 내용이라 회수한 키가 되살아나지 않습니다.
- 둘 다 망가지면 **모두 거부**합니다(fail-closed). 복구: 백업 매체에서 두 파일을 되돌리거나,
  `client add` 로 키를 다시 발급합니다(이전 키 파일은 더 이상 통하지 않습니다).
- 운영 백업 대상에 `~/.fastunnel/clients.json` 과 `.bak` 을 넣으세요.

## 키 파일 (`client.key`)

```json
{"id": "kim", "key": "<base64 32바이트>"}
```

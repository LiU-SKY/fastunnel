# 터널 접속 도우미

이 폴더를 통째로 전달하면, 받는 사람은 **`connect.cmd` 더블클릭** 한 번으로
서버에 열려 있는 포트에 접속할 수 있습니다. 설치할 것도, 주소를 물어볼 일도 없습니다.

```
client/
├── connect.cmd    ← 받는 사람이 더블클릭하는 파일
├── connect.ps1    ← 실제 동작 (윈도우 기본 파워셸)
└── server.txt     ← 터널 정보를 알려 주는 고정 URL (배포 전에 채워 두세요)
```

## 어떻게 동작하나

```
server.txt 의 고정 URL
        │
        ▼
{ "tunnels": [ { "port": 25565, "address": "지금-열린-주소" }, ... ] }
        │
   cloudflared 자동 내려받기 (처음 한 번)
        │
   열린 터널마다 통로 생성
        ▼
   127.0.0.1:25565  ← 이 주소로 접속
```

터널 주소는 서버를 다시 켤 때마다 바뀝니다. 그래서 주소를 직접 알려 주지 않고,
**"지금 무엇이 열려 있는지" 알려 주는 URL 하나를 고정**해 두고 그때그때 읽어 옵니다.
**포트 목록도 그 URL에서 받아오므로**, 서버에서 포트를 바꿔도 받는 사람은 아무것도 안 해도 됩니다.

## 배포하는 사람이 할 일

1. 서버에서 게시 설정을 한 번 합니다.

   ```bash
   python3 tools/publish-setup.py --gist-id <GIST_ID> --owner <깃허브사용자명>
   ```

2. 출력된 URL 을 `server.txt` 첫 줄에 넣습니다.

3. `client/` 폴더를 압축해서 전달합니다.

## 쓰는 사람이 할 일

`connect.cmd` 더블클릭 → 표에 나온 **`127.0.0.1:포트`** 로 접속.

**따로 설치할 것은 없습니다.** cloudflared 가 없으면 처음 한 번 자동으로 내려받습니다
(약 50MB, `%LOCALAPPDATA%	unnel-connect\`). 두 번째부터는 바로 연결됩니다.
이미 설치돼 있으면 그것을 그대로 씁니다. 32비트 윈도우도 알아서 맞는 파일을 받습니다.

> `localhost` 로 넣으면 안 될 수 있습니다. 윈도우에서 `localhost` 는 IPv6(`::1`)로 먼저
> 풀리는데 통로는 IPv4(`127.0.0.1`)에만 열리기 때문입니다. **숫자 주소를 그대로** 쓰세요.

**쓰는 동안 창을 켜 두어야 합니다.** 닫으면 접속이 끊깁니다.

### 표에 나오는 상태

| 상태 | 뜻 |
|---|---|
| 정상 | 통로가 열렸고 반대편 프로그램도 응답합니다 |
| 응답 없음 | 통로는 열렸지만 저쪽 프로그램이 안 켜져 있습니다. 잠시 뒤 다시 실행 |
| 실패 | 통로 자체를 못 만들었습니다. 서버가 꺼졌거나 주소가 막 바뀐 직후 |

### 옵션

```powershell
.\connect.ps1 -Only 25565        # 특정 포트만 연결
.\connect.ps1 -LocalPort 30000   # 내 PC에서 쓸 첫 포트 지정
```

## 자주 나오는 상황

| 증상 | 원인과 대처 |
|---|---|
| "정보를 받아오지 못했습니다" | 인터넷 문제이거나 `server.txt` URL 오타. 마지막으로 알던 정보로 한 번 더 시도합니다 |
| "cloudflared 를 내려받지 못했습니다" | 회사·학교망에서 깃허브가 막혔을 수 있습니다. 직접 설치하면 그것을 씁니다 |
| 원격과 다른 번호가 나옴 | 그 포트를 이미 쓰고 있어서 옆 번호로 비킨 것. 표에 나온 번호로 접속하면 됩니다 |
| "정상" 인데 프로그램이 못 붙음 | 주소에 `localhost` 를 넣지 않았는지 확인. `127.0.0.1:포트` 여야 합니다 |
| 다른 PC 에서 접속 시도 | `127.0.0.1` 은 이 창을 띄운 PC 자신입니다. 각자 자기 PC 에서 실행해야 합니다 |
| 파워셸 실행 정책 오류 | `.cmd` 가 `-ExecutionPolicy Bypass` 로 실행하므로 보통 안 납니다 |

## 배포 전에 반드시 읽을 것 (보안)

**이 폴더를 받은 사람은 터널에 열린 모든 포트에 접속할 수 있습니다.**
터널 자체에는 인증이 없습니다. 클라이언트는 열쇠가 아니라 **자물쇠가 없다는 사실**을 편하게 만들어 줄 뿐입니다.

### 폴더 안에 비밀값은 없습니다

`server.txt` 에 들어가는 것은 gist 의 **읽기 전용 공개 URL** 하나뿐입니다.
게시용 GitHub 토큰은 서버의 `~/.fastunnel/config.json`(권한 600)에만 있고 배포물에 포함되지 않습니다.
다만 **그 URL 자체가 "지금 서버 주소가 뭔지" 알려 주는 열쇠**입니다.

### 그래서 지켜야 할 것

1. **공개할 생각이 없는 포트는 터널에 올리지 마세요.**
   SSH(22), 데이터베이스, 관리자 페이지 같은 것은 절대 열지 마세요.
   클라이언트는 게시된 포트를 **전부** 자동으로 연결합니다.

2. **서비스 자체에 인증을 걸어 두세요.**
   터널에는 인증이 없으므로, 접근 제어는 서비스가 해야 합니다.
   (게임 서버라면 화이트리스트, 웹이라면 로그인)

3. **`server.txt` 가 채워진 폴더를 공개 저장소에 올리지 마세요.**
   저장소에는 빈 템플릿만 두고, URL 은 배포용 압축본에만 넣으세요.

4. **한 번 나간 것은 회수되지 않습니다.**
   받은 사람은 언제든 다시 접속할 수 있습니다. 끊으려면 **gist 를 지우고 새로 만들어**
   새 URL 로 다시 배포해야 합니다. (또는 서버에서 터널을 닫으면 그때부터 아무도 못 붙습니다)

5. **불특정 다수에게 뿌리는 것은 권하지 않습니다.**
   아는 사람에게 개별 전달하는 정도가 적당합니다.

### 접근 제어가 꼭 필요하다면

Cloudflare Zero Trust(무료, 50명까지)의 Access 정책을 터널 앞에 걸면
접속할 때 로그인을 요구할 수 있습니다. 대신 받는 사람이 브라우저 인증을 한 번 거쳐야 해서
"더블클릭 한 번" 은 아니게 됩니다. 필요하시면 그 구성으로 바꿀 수 있습니다.
